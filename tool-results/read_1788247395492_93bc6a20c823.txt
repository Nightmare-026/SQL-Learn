    47→## 1. Executive Summary
    48→
    49→### 1.1 Vision
    50→
    51→Build a **complete, free, browser-based SQL learning platform** that takes users from zero knowledge to industry-level SQL expertise through 60 structured modules, interactive practice console, and real-world projects — all without requiring signup, servers, or payment.
    52→
    53→### 1.2 Problem Statement
    54→
    55→| Current Pain Point | Our Solution |
    56→|---|---|
    57→| SQL tutorials are theory-heavy, practice-light | 300 interactive practice tasks with live validation |
    58→| Practice environments require setup (MySQL/PostgreSQL install) | Browser-based SQLite (sql.js) — zero setup |
    59→| Content jumps from basic to advanced without progression | 60 micro-modules with gradual difficulty |
    60→| No feedback on wrong queries | Friendly error explanations + SQLite raw errors |
    61→| English-only content excludes Hindi speakers | Full dual-language toggle (EN/HI) |
    62→| Progress lost when switching devices | localStorage + backup/export system |
    63→
    64→### 1.3 Core Value Propositions
    65→
    66→| # | Value | Implementation |
    67→|---|---|---|
    68→| 1 | **Zero Friction Start** | No signup, no server, no payment — instant learning |
    69→| 2 | **Complete Journey** | 60 modules: Beginner (20) → Intermediate (20) → Advanced (20) |
    70→| 3 | **Real Practice** | 3-panel IDE console with live SQLite execution |
    71→| 4 | **Smart Validation** | Result-matching engine (not exact string match) |
    72→| 5 | **Progressive Learning** | 5 tasks per module (Very Easy → Very Hard) |
    73→| 6 | **Dual Language** | Full English + Hinglish content toggle |
    74→| 7 | **100% Free & Offline** | Client-side only, works without internet after load |
    75→| 8 | **Industry-Ready** | 10 projects including capstone BI system |
    76→
    77→### 1.4 Target Users
    78→
    79→| Persona | Description | Primary Need |
    80→|---|---|---|
    81→| **Complete Beginner** | Never touched SQL, possibly student or career switcher | Gentle, structured introduction |
    82→| **College Student** | Learning DBMS in curriculum, needs practice | Exam-oriented clear explanations |
    83→| **Job Seeker** | Preparing for data analyst/developer interviews | Practical query skills, common patterns |
    84→| **Working Developer** | Knows programming, weak in SQL | Quick reference, advanced topics |
    85→
    86→### 1.5 Success Definition
    87→
    88→- User completes Beginner level without external help
    89→- User can write JOIN, GROUP BY, subquery queries confidently
    90→- User can solve real business problems with SQL after Capstone
    91→- Platform feels professional (Coursera-level UI quality)

   172→### 3.2 Why These Choices
   173→
   174→| Technology | Reason | Alternative Rejected |
   175→|---|---|---|
   176→| **React 18** | Industry standard, huge ecosystem, shadcn/ui compatibility | Vue (smaller ecosystem for this use) |
   177→| **TypeScript** | Type safety for 60-module content structures, catches content bugs | JavaScript (runtime errors in content) |
   178→| **Tailwind CSS** | Rapid UI development, consistent design tokens, small bundle | CSS Modules (slower development) |
   179→| **shadcn/ui** | Beautiful accessible components, copy-paste ownership, Radix-based | Material UI (heavier, opinionated) |
   180→| **sql.js** | SQLite in browser, WASM = fast, no server needed | Server-based MySQL (hosting cost, complexity) |
   181→| **Zustand** | Lightweight, simple API, perfect for this scale | Redux (overkill), Context (performance) |
   182→| **Vite** | Fastest build tool, excellent DX | Webpack (slower, more config) |

   320→### 4.2 Data Flow: Query Execution
   321→
   322→```
   323→USER FLOW (Practice Task):
   324→
   325→[1] User types query
   326→     │
   327→     ▼
   328→[2] Clicks "RUN" button
   329→     │
   330→     ▼
   331→[3] Query sent to sql.js engine
   332→     │
   333→     ├── ERROR path:
   334→     │   ├── SQLite error captured
   335→     │   ├── Error pattern matcher runs
   336→     │   │   (detects common typos: FORM→FROM, etc.)
   337→     │   └── Friendly explanation generated
   338→     │   └── Display: Friendly message + Raw technical error
   339→     │
   340→     └── SUCCESS path:
   341→         ├── Query executes
   342→         ├── Result set extracted (rows + columns)
   343→         │
   344→         ├── NORMALIZATION:
   345→         │   ├── Trim whitespace in string values
   346→         │   ├── Round decimals to tolerance (0.01)
   347→         │   ├── Sort rows (if no ORDER BY in expected)
   348→         │   └── Map column names (if aliases expected)
   349→         │
   350→         ├── COMPARISON:
   351→         │   ├── Column count check
   352→         │   ├── Column names check (if required)
   353→         │   ├── Row count check
   354→         │   └── Cell-by-cell value comparison
   355→         │
   356→         └── RESULT:
   357→             ├── MATCH → "✅ Correct!" + Next task unlock
   358→             └── NO MATCH → "❌ Output doesn't match" +
   359→                 Diff view (Expected vs Got) +
   360→                 Hint suggestion
   361→```

   408→## 5. Database Design
   409→
   410→### 5.1 Dataset Progression Strategy
   411→
   412→| Level | Database | Complexity | Rationale |
   413→|---|---|---|---|
   414→| Beginner (M1-20) | School | Simple (5 tables) | Relatable context, simple columns |
   415→| Intermediate (M21-40) | E-Commerce | Medium (6 tables) | Real-world, natural JOIN scenarios |
   416→| Advanced (M41-60) | E-Commerce + Extensions | Complex (10 tables) | Complex relationships, analytics |
   417→
   418→### 5.2 School Database Schema (Beginner)
   419→
   420→```sql
   421→-- ============================================
   422→-- SCHOOL DATABASE — Beginner Modules (M1-M20)
   423→-- 5 Tables, ~275 total records
   424→-- ============================================
   425→
   426→CREATE TABLE students (
   427→    id INTEGER PRIMARY KEY,
   428→    name TEXT NOT NULL,
   429→    grade TEXT CHECK(grade IN ('A', 'B', 'C', 'D', 'F')),
   430→    city TEXT,
   431→    age INTEGER CHECK(age BETWEEN 15 AND 25),
   432→    email TEXT,
   433→    enrollment_date DATE
   434→);
   435→
   436→CREATE TABLE teachers (
   437→    id INTEGER PRIMARY KEY,
   438→    name TEXT NOT NULL,
   439→    subject TEXT,
   440→    experience_years INTEGER,
   441→    salary DECIMAL(10, 2),
   442→    hire_date DATE
   443→);
   444→
   445→CREATE TABLE departments (
   446→    id INTEGER PRIMARY KEY,
   447→    name TEXT NOT NULL,
   448→    head_teacher_id INTEGER,
   449→    budget DECIMAL(10, 2),
   450→    FOREIGN KEY (head_teacher_id) REFERENCES teachers(id)
   451→);
   452→
   453→CREATE TABLE courses (
   454→    id INTEGER PRIMARY KEY,
   455→    name TEXT NOT NULL,
   456→    teacher_id INTEGER,
   457→    department_id INTEGER,
   458→    credits INTEGER CHECK(credits BETWEEN 1 AND 5),
   459→    max_students INTEGER DEFAULT 30,
   460→    FOREIGN KEY (teacher_id) REFERENCES teachers(id),
   461→    FOREIGN KEY (department_id) REFERENCES departments(id)
   462→);
   463→
   464→CREATE TABLE enrollments (
   465→    id INTEGER PRIMARY KEY,
   466→    student_id INTEGER,
   467→    course_id INTEGER,
   468→    enrollment_date DATE,
   469→    score DECIMAL(5, 2),
   470→    grade TEXT,
   471→    FOREIGN KEY (student_id) REFERENCES students(id),
   472→    FOREIGN KEY (course_id) REFERENCES courses(id)
   473→);
   474→
   475→-- INDEXES for practice demonstration
   476→CREATE INDEX idx_students_city ON students(city);
   477→CREATE INDEX idx_enrollments_student ON enrollments(student_id);

   508→
   509→```sql
   510→-- ============================================
   511→-- E-COMMERCE DATABASE — Intermediate (M21-M40)

   534→    name TEXT NOT NULL,

  1003→## 9. Query Validation Engine
  1004→
  1005→### 9.1 Validation Algorithm
  1006→
  1007→```typescript
  1008→// PSEUDO-CODE — Actual implementation in TypeScript
  1009→
  1010→async function validateUserQuery(
  1011→  userQuery: string,
  1012→  task: PracticeTask,
  1013→  dbInstance: Database
  1014→): Promise<ValidationResult> {
  1015→
  1016→  // STEP 1: Execute user's query
  1017→  let userResult: QueryResult;
  1018→  try {
  1019→    userResult = await dbInstance.execute(userQuery);
  1020→  } catch (error) {
  1021→    // STEP 2a: Handle execution error
  1022→    return {
  1023→      status: 'ERROR',
  1024→      friendlyMessage: generateFriendlyError(error),
  1025→      technicalError: error.message,
  1026→      suggestion: detectCommonMistake(error) // FORM→FROM etc.
  1027→    };
  1028→  }
  1029→
  1030→  // STEP 2b: Query executed successfully, now compare results
  1031→  const expected = task.expectedResult;
  1032→  const rules = task.validation;
  1033→
  1034→  // STEP 3: Column comparison
  1035→  const columnCheck = compareColumns(
  1036→    userResult.columns,
  1037→    expected.columns,
  1038→    rules
  1039→  );
  1040→
  1041→  if (!columnCheck.match) {
  1042→    return {
  1043→      status: 'WRONG',
  1044→      message: 'Column structure doesn\'t match',
  1045→      diff: generateColumnDiff(userResult, expected)
  1046→    };
  1047→  }
  1048→
  1049→  // STEP 4: Row comparison
  1050→  const normalizedUser = normalizeRows(userResult.rows, rules);
  1051→  const normalizedExpected = normalizeRows(expected.rows, rules);
  1052→
  1053→  const rowCheck = compareRows(normalizedUser, normalizedExpected, rules);
  1054→
  1055→  if (!rowCheck.match) {
  1056→    return {
  1057→      status: 'WRONG',
  1058→      message: 'Output rows don\'t match expected result',
  1059→      diff: generateRowDiff(normalizedUser, normalizedExpected)
  1060→    };
  1061→  }
  1062→
  1063→  // STEP 5: Everything matches!
  1064→  return {
  1065→    status: 'SUCCESS',
  1066→    message: '✅ Correct! Well done!',
  1067→    rowCount: userResult.rows.length
  1068→  };
  1069→}
  1070→```
  1071→
  1072→### 9.2 Result Normalization Rules
  1073→
  1074→| Rule | Default | When to Change | Example |
  1075→|---|---|---|---|
  1076→| `ignoreColumnOrder` | `false` | `true` if task doesn't specify column order | Task: "show name and salary" — either order OK |
  1077→| `ignoreRowOrder` | `true` | `false` if task has ORDER BY requirement | Task: "sort by salary DESC" — order matters |
  1078→| `caseSensitiveData` | `false` | `true` for case-specific tasks | Task: "match exact product name case" |
  1079→| `trimWhitespace` | `true` | Never change | 'Rahul ' == 'Rahul' |
  1080→| `numericTolerance` | `0.01` | `0.001` for precise calculations | AVG(salary) = 52345.67 vs 52345.68 |
  1081→| `checkColumnNames` | `false` | `true` if aliases required | Task: "show as 'total_salary'" |
  1082→
  1083→### 9.3 Comparison Logic Detail
  1084→
  1085→```typescript
  1086→function compareColumns(userCols, expectedCols, rules): boolean {
  1087→  if (rules.checkColumnNames) {
  1088→    // Exact column name matching (including aliases)
  1089→    return arraysEqual(userCols, expectedCols);
  1090→  }
  1091→  // Just count check
  1092→  return userCols.length === expectedCols.length;
  1093→}
  1094→
  1095→function normalizeRows(rows, rules): NormalizedRow[] {
  1096→  return rows.map(row =>
  1097→    row.map(cell => {
  1098→      if (typeof cell === 'string') {
  1099→        if (rules.trimWhitespace) cell = cell.trim();
  1100→        if (!rules.caseSensitiveData) cell = cell.toLowerCase();
  1101→      }
  1102→      if (typeof cell === 'number') {
  1103→        cell = round(cell, rules.numericTolerance);
  1104→      }
  1105→      if (cell === null || cell === undefined) {
  1106→        cell = null; // Normalize both null and undefined
  1107→      }
  1108→      return cell;
  1109→    })
  1110→  );
  1111→}
  1112→
  1113→function compareRows(userRows, expectedRows, rules): boolean {
  1114→  if (userRows.length !== expectedRows.length) return false;
  1115→
  1116→  let userSorted = userRows;
  1117→  let expectedSorted = expectedRows;
  1118→
  1119→  if (rules.ignoreRowOrder) {
  1120→    // Sort both by stringified representation for comparison
  1121→    userSorted = [...userRows].sort((a, b) => JSON.stringify(a).localeCompare(JSON.stringify(b)));
  1122→    expectedSorted = [...expectedRows].sort((a, b) => JSON.stringify(a).localeCompare(JSON.stringify(b)));
  1123→  }
  1124→
  1125→  return userSorted.every((row, i) =>
  1126→    row.every((cell, j) => cellEquals(cell, expectedSorted[i][j]))
  1127→  );
  1128→}
  1129→```

  1263→
  1264→| Error Pattern | SQLite Message Fragment | Friendly Suggestion |
  1265→|---|---|---|
  1266→| `FORM` instead of `FROM` | `near "FORM": syntax error` | "Aapne FORM likha hai — FROM hona chahiye" |
  1267→| `WERE` instead of `WHERE` | `near "WERE": syntax error` | "WERE → WHERE spelling check karo" |

  1269→| Missing quotes | `near "A": syntax error` | "String values ko quotes me rakho: 'A' ya \"A\"" |

  1272→| Unclosed string | `unterminated string` | "Quote close karna bhool gaye — '..." ' missing" |
  1273→| Invalid operator | `near "<>=": syntax error` | "Invalid operator. Valid: =, <>, <, >, <=, >=" |

  1933→function calculateProgress(progress: ProgressState): ProgressSummary {
  1934→  const completedModules = Object.values(progress.modules)
  1935→    .filter(m => m.status === 'completed').length;
  1936→
  1937→  const totalTasks = countAllTasks(); // 300
  1938→  const completedTasks = Object.values(progress.modules)
  1939→    .reduce((sum, m) => sum + m.tasksCompleted.length, 0);
  1940→
  1941→  return {
  1942→    overallPercent: (completedModules / 60) * 100,
  1943→    levelProgress: {
  1944→      beginner: countCompleted('beginner') / 20,
  1945→      intermediate: countCompleted('intermediate') / 20,
  1946→      advanced: countCompleted('advanced') / 20
  1947→    },
  1948→    tasksCompleted: `${completedTasks}/${totalTasks}`,
  1949→    projectsCompleted: countCompletedProjects() / 10
  1950→  };
  1951→}

  1954→### 18.3 Module Unlock Logic
  1955→
  1956→```typescript
  1957→function isModuleUnlocked(moduleId: string, progress: ProgressState): boolean {
  1958→  const module = getModuleById(moduleId);
  1959→
  1960→  // Module 1 always unlocked
  1961→  if (module.number === 1) return true;
  1962→
  1963→  // Previous module must be complete
  1964→  const prevModule = getModuleById(`module-${module.number - 1}`);
  1965→  const prevProgress = progress.modules[prevModule.id];
  1966→
  1967→  if (!prevProgress || prevProgress.status !== 'completed') {
  1968→    return false;
  1969→  }
  1970→
  1971→  // Level boundary check
  1972→  // Module 21 (Intermediate start) requires ALL beginner modules complete
  1973→  if (module.number === 21) {
  1974→    return areAllModulesCompleted('beginner', progress);
  1975→  }
  1976→  if (module.number === 41) {
  1977→    return areAllModulesCompleted('intermediate', progress);
  1978→  }
  1979→
  1980→  return true;
  1981→}
